Enforcement

How a stream over the limit is stopped. The recommended defaults work for every client, including ones that ignore remote stop commands.

BETA — the HTTP-level hard block below is new. It has been tested but is still maturing. If a legitimate stream is ever wrongly blocked, turn Hard block off to fall back to the classic behaviour (stop command after the stream starts).
Recommended, on by default. Rejects the over-limit stream before a single byte is sent, so it works on every client (Swiftfin, Infuse, external players, custom apps...). Turn off to use only the classic stop-command behaviour.
On by default. Denies the stream during setup so the client shows a clean "not allowed" dialog instead of failing mid-load. Requires Hard block.
On by default. Stops the server-side ffmpeg process feeding a blocked stream — a safety net for clients that ignore the stop command.
Off by default. The most aggressive option: revokes the device's token (also cuts direct-play), but the user has to sign in again on that device.
Off by default. By default a request whose user can't be identified is let through (fail-open). Enable to reject those too — safer, but may break unusual clients. Only turn on if you need it.
On by default. Administrators are never limited, whatever their own limit or the default limit. Turn off to apply limits to administrators too.
On by default. Adds an entry to Dashboard > Activity when a stream is blocked, with the user, device, client and IP address. At most one entry per user and device every 5 minutes.

Blocked message

What a blocked user sees. Set the wording once below; the two options control where it is shown.

Heading of the popup shown when a stream is blocked. Placeholders allowed (see below).
Body of the popup, e.g. "You have reached your simultaneous streams limit."
Placeholders, in the title and the text: {{user}} the user's name, {{active}} the streams already playing, {{limit}} the user's limit, {{devices}} the other devices playing. Example: {{user}}, you are already watching on {{devices}} ({{active}}/{{limit}}).
Where the message appears
Recommended, on by default. Displays a single clean popup with your title/text above — instead of the web client's own generic "not allowed" dialog. Web clients only (browser, Android app webview, iOS web). Added to the web client on the fly — no server restart needed and it works with read-only web folders; just refresh the browser after changing this.
Off by default. Sends a Jellyfin "display message" command. Only some native apps show it (e.g. Android TV, as a toast), and it adds a second popup on web clients. Leave off unless you specifically want it for a native client.
Note on native apps. Swiftfin, AFinity, Streamyfin, Infuse and other native clients display their own error screen when a stream is blocked, and no server plugin can change or hide it — the block still works, only the wording is theirs. Custom wording is possible on web clients only.
